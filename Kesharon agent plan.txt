## Public interfaces and locked behavior

- Retain protocol version `1` because the extended contract is uncommitted, version `0.0.0`, and has no published consumer. Stop and introduce a versioned compatibility plan if an external consumer or artifact is discovered.
- Keep:

  - `ProjectSnapshot { id, displayName, canonicalRoot, trusted }`
  - `OperationSnapshot { requestId, kind, status }`
  - `WorkspaceSnapshot { streamId, lastSequence, project, activeOperations }`
  - `operationStarted`, `projectOpened`, `operationCancelled`, and `operationFailed`
  - `CancelRequest`, `SubscribeEvents`, and the three cancellation outcomes
  - UUIDv7 daemon `streamId`, sequences starting at one, a 64-message buffer, an eight-connection cap, and a 256-entry completion ledger

- Replace stringly typed error codes with a shared Rust enum and TypeScript union: `invalidRequest`, `notGitRepository`, `projectPathUnavailable`, `operationCancelled`, `requestInProgress`, `serverBusy`, and `internalError`.
- Resolve the earlier contract ambiguity by keeping a missing cancellation target as the successful `notFound` cancellation outcome. Do not add an unused `requestNotFound` error.
- Define idempotency precisely:

  - Same key and identical mutation: replay the stored outcome under the retry’s current `requestId`, emitting no additional event.
  - Same key with different method or arguments: return `invalidRequest`.
  - Identical mutation still running: return `requestInProgress`.
  - Eviction after 256 completed mutations permits later re-execution.

- Allow exactly one authoritative daemon event subscriber. A new subscription atomically captures its snapshot and replaces the prior subscriber; buffer overflow disconnects it.
- Add the frontend-facing bridge:

  ```ts
  interface DesktopBridge {
    getHealth(): Promise<HealthSnapshot>;
    chooseProjectDirectory(): Promise<string | null>;
    openProject(path: string): {
      requestId: string;
      completion: Promise<ProjectSnapshot>;
    };
    cancelRequest(targetRequestId: string): Promise<CancellationOutcome>;
    subscribeDaemonEvents(
      onUpdate: (update: DaemonStreamUpdate) => void
    ): Promise<void>;
  }

  type DaemonStreamUpdate =
    | { type: "message"; message: StreamMessage }
    | { type: "reconnecting" }
    | { type: "unavailable"; message: string };
  ```

- The bridge generates request and idempotency UUIDs before invoking Tauri, making cancellation immediately addressable.
- The TypeScript protocol package must decode generic responses, structured failures, project-open results, cancellation results, and stream messages rather than trusting `unknown`.

## Phase 1 — Complete the concurrent daemon session and IPC contract

**Current behavior and diagnosis**

The session core already stores project state, active operations, sequence numbers, subscribers, and completion entries. Its tests bypass production transport concurrency. In production, `main.rs` repeatedly invokes a method that accepts and fully serves one connection; a subscription then blocks in `Receiver::recv()`, preventing later command connections.

Other gaps are untested completion-ledger eviction, idempotency-key collisions, subscriber overflow, subscriber replacement, failure terminal events, connection saturation, and actual process-level concurrent cancellation.

**Repository evidence**

- [daemon library](<D:/Proiecte AI/Kesharon Agent/.worktrees/m0-m1-foundation/crates/kesharon-daemon/src/lib.rs:116>) accepts and serves synchronously.
- [daemon main loop](<D:/Proiecte AI/Kesharon Agent/.worktrees/m0-m1-foundation/crates/kesharon-daemon/src/main.rs:46>) does not spawn bounded handlers.
- [session tests](<D:/Proiecte AI/Kesharon Agent/.worktrees/m0-m1-foundation/crates/kesharon-daemon/tests/session.rs:132>) invoke `DaemonSession` directly from separate test threads.
- `LocalServer::accept_with_timeout` currently blocks in `accept()` before applying nonblocking mode, and `connect_with_timeout` performs the connection before applying its deadline.

**Implementation sequence**

1. Start with failing tests for:

   - A real daemon process retaining a subscription while answering health and open requests.
   - Cancellation arriving through a second IPC connection while open is blocked.
   - An authenticated ninth concurrent connection receiving `serverBusy`.
   - A second subscriber replacing and closing the first.
   - Buffer overflow ending the subscriber and reconnect snapshot covering skipped events.
   - Atomic subscription during an active operation.
   - Exactly one terminal event on success, cancellation, and repository failure.
   - Failed or cancelled replacement preserving the previous project.
   - Idempotency replay, key/payload conflict, in-flight duplicate, request correlation, and 256-entry eviction.

2. Complete shared JSON fixtures for every request, response, structured error, snapshot, and event. Add generic TypeScript response decoding and typed error codes.
3. Store mutation fingerprints with in-flight and completed idempotency records. Store replayable outcomes independently from request correlation IDs.
4. Replace the subscriber vector with one optional bounded sender. Snapshot capture and subscriber replacement must occur under the same session lock.
5. Remove request-path panics. Mutex poisoning, impossible sequence creation, and unexpected adapter failures must return `internalError` or terminate only the affected authenticated connection without corrupting shared state.
6. Split the growing daemon module by responsibility: session state, filesystem repository adapter, and bounded server runtime; keep `lib.rs` as the narrow public surface.
7. Use `interprocess` listener nonblocking modes to implement a real accept deadline, and `ConnectOptions` with `ConnectWaitMode::Timeout` for bounded client connection attempts.
8. Add a maximum of eight active connection permits. Each accepted connection is served on a worker thread; an authenticated excess request receives `serverBusy`.
9. Authenticate before returning any structured response. Preserve the 8 MiB frame limit and per-frame read/write deadlines.
10. Keep the filesystem adapter at the daemon boundary: canonicalize the selected directory, accept `.git` as a directory or linked-worktree file, reject other roots, and always create the project with `trusted=false`.
11. Run focused gates, then the full Rust workspace. Commit as `fix: complete concurrent daemon session`.

**Invariants and compatibility**

- Domain remains standard-library-only; application remains infrastructure-free.
- The previous project changes only after successful inspection and uncancelled construction.
- One started and exactly one terminal event are emitted per accepted operation.
- Sequence gaps are never inferred over; the consumer reconnects for a snapshot.
- Authentication failure closes the connection without an error payload.
- State and idempotency remain process-memory-only until M2.
- No Tokio or additional async runtime should be introduced for the daemon.
- Preserve `unsafe_code = "forbid"`.

3. Generalize `DaemonClient` to send correlated open/cancel requests and to establish an authenticated subscription that validates:

   - `SubscriptionReady.streamId`
   - The initial snapshot’s matching stream

5. Forward stream data through a typed Tauri `Channel<DaemonStreamUpdate>`. Maintain one subscription generation; a newer subscription invalidates the prior worker.
6. On EOF, overflow-induced closure, stream mismatch, sequence gap, or daemon restart:

   - Emit `reconnecting`.
   - Re-read the current host `DaemonClient`, rather than retaining the old endpoint/token.
   - Retry after 50 ms, doubling to a maximum of one second.
   - Accept no events until a new authoritative snapshot arrives.
   - Emit `unavailable` if the host’s one-restart budget is exhausted.

8. Implement the bridge contract above. Validate all `unknown` Tauri responses through the protocol package and require response `requestId` correlation.
9. Put workspace transition logic in a focused reducer module:

   - Snapshot replaces state.
   - Matching next event updates project/active operations.
   - Gap or stream mismatch requests reconnection and applies nothing.
   - Terminal failure/cancellation removes the active operation and preserves the prior project.
   - A new empty stream after a previously open project shows “Daemon restarted; reopen repository.”

10. Wire both “Add project” and “Open repository” controls. Picker cancellation changes nothing.
11. During opening, show canonical progress and a Cancel control. On success, show canonical identity and enable local task text entry; keep actual “Prepare plan” execution disabled and labelled as a later milestone.

## Phase 3 — Prove Windows same-user pipe isolation

**Current behavior and diagnosis**

The worktree passes `D:P(A;;GA;;;OW)(A;;GA;;;SY)` into the Windows listener and tests only that the constant has that value. It does not inspect effective behavior or prove denial to a second user.

Microsoft documents that a default named-pipe descriptor grants read access to Everyone and Anonymous and that client access is checked against the pipe DACL. [Microsoft named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) `OW` denotes the current Owner Rights SID, distinct from the inheritable Creator Owner SID. [Microsoft SID definitions](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-identifiers)

**Implementation sequence**

1. Retain the protected SDDL and safe `interprocess` descriptor API; do not introduce Rust `unsafe`.
2. Add a Windows-only integration script that:

   - Builds/launches an ephemeral daemon endpoint under the runner account.
   - Proves the current account can connect and complete authenticated health.
   - Creates a random local secondary account.
   - Runs a bounded named-pipe connection probe as that account.
   - Requires access denial before authentication.
   - Records distinct results for denied, timed out, unexpectedly connected, and infrastructure failure.
   - Deletes the scheduled task/process, result file, and local account in `finally`.

3. Add a dedicated `windows-pipe-acl` CI job rather than hiding the proof inside ordinary unit tests.
4. Keep the static SDDL test as a contract test, but do not treat it as security evidence.
5. Correct documentation to describe `OW` as Owner Rights/current owner, not the Creator Owner placeholder.
6. Commit as `test: verify Windows pipe isolation`.

**Risks, non-goals, and stop conditions**

- This phase proves local cross-account denial, not remote named-pipe policy, AppContainer isolation, or elevated automation.
- Do not weaken the DACL to make CI easier.
- Stop if GitHub-hosted runners prohibit account creation or alternate-user launch. Re-plan for a controlled Windows runner or a reviewed native test harness.
- Stop if the effective owner differs from the launching desktop user or a secondary account connects successfully.
- Treat cleanup failure as a failed security job.

**Verification**


Success requires same-user authenticated success, secondary-user connection denial, bounded execution, and verified cleanup.
